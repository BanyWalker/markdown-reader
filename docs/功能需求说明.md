# MD Reader 功能需求说明

## 1. 目标与范围

本期面向 Windows 桌面端 MD Reader，在现有本地 Markdown 阅读能力上新增以下能力：

1. 常见 Markdown 社区渲染扩展的**预览**，包括 ECharts；
2. 按文档记忆阅读滚动位置；
3. Markdown / 文本源码编辑与显式保存。

不在本期范围内：插件市场、用户安装插件、插件启停管理、从网络下载或执行插件代码、协作编辑、云同步、自动保存到磁盘、所见即所得编辑器和图表交互式配置器。

### 1.1 现有能力与兼容原则

应用当前支持本地 Markdown、文本文件、GFM 表格和任务列表、代码高亮、目录浏览、阅读/源码视图切换，以及浅色/深色/木色主题。新增能力必须：

- 继续支持现有 `.md`、`.markdown`、`.mdx`、`.mdown`、`.mkdn` 与现有文本扩展名；
- 不改变普通 fenced code block（围栏代码块）的展示；
- 在不支持、解析失败或资源不可用时保留文档其余内容可读；
- 仅处理用户已经通过打开文件/文件夹操作授权访问的本地文档。

## 2. 社区渲染扩展（仅预览）

### 2.1 产品边界

“插件”指随应用版本打包、由开发者维护的 Markdown 渲染扩展，而非用户可管理的运行时插件。应用不提供插件管理页、插件目录、安装包导入、网络市场、开关、配置脚本或第三方 JavaScript 执行能力。

每项扩展在 Markdown 渲染阶段识别特定语法并生成受控 DOM；脚本库随应用本地打包。所有扩展都应在阅读视图和编辑后切回阅读视图时生效，源码编辑视图始终显示原始 Markdown。

### 2.2 首期内置扩展

| 优先级 | 能力/推荐实现 | Markdown 写法 | 预览行为 |
| --- | --- | --- | --- |
| P0 | ECharts（`echarts`） | ```` ```echarts\n{ "xAxis": {}, "yAxis": {}, "series": [{ "type": "bar", "data": [12, 20] }] }\n``` ```` | 将严格 JSON 的 option 渲染为自适应图表。 |
| P0 | Mermaid（`mermaid`） | ```` ```mermaid\nflowchart LR\n  A[开始] --> B[结束]\n``` ```` | 渲染流程图、时序图、类图、状态图等 Mermaid 支持的类型。 |
| P0 | 数学公式（`markdown-it-katex` 或等价实现） | 行内：`$E=mc^2$`；块级：`$$\n\\int_0^1 x^2 dx\n$$` | 使用 KaTeX 渲染；不执行 LaTex 宏中的任意脚本。 |
| P1 | 脚注（`markdown-it-footnote`） | `正文[^note]` 与 `[^note]: 脚注内容` | 生成脚注引用、脚注区和返回链接。 |
| P1 | Emoji（`markdown-it-emoji`） | `:smile:`、`:rocket:` | 替换为标准 Unicode Emoji，不请求外部图片。 |
| P1 | 提示容器（`markdown-it-container`） | `::: tip\n提示内容\n:::`；同理 `info`、`warning`、`danger` | 生成带语义和主题适配样式的提示块。 |
| P1 | 标记、上下标（`markdown-it-mark`、`markdown-it-sub`、`markdown-it-sup`） | `==高亮==`、`H~2~O`、`x^2^` | 生成语义化 HTML 与主题适配样式。 |

说明：现有 GFM 表格、任务列表、删除线及代码高亮继续保留，不重复作为新增插件能力。PlantUML、Graphviz、Vega/Vega-Lite、代码运行器等因需要额外二进制、远程服务或更复杂的安全隔离，不进入首期；后续须独立评审再引入。

### 2.3 ECharts 详细要求

1. **语法识别**：仅识别信息字符串恰为 `echarts` 的 fenced code block。首期不使用 `chart`、`js`、`javascript` 等别名，避免将普通代码误执行为图表。
2. **数据格式**：代码块内容必须是 JSON object，作为 `echarts.setOption(option)` 的 option。JSON 中允许注释以外的标准 JSON 值；不支持函数、变量、模板表达式、`new Date()`、外部数据请求或 JavaScript 对象字面量扩展。
3. **示例**：

   ````markdown
   ```echarts
   {
     "title": { "text": "月度阅读量" },
     "tooltip": { "trigger": "axis" },
     "xAxis": { "type": "category", "data": ["一月", "二月", "三月"] },
     "yAxis": { "type": "value" },
     "series": [{ "type": "line", "smooth": true, "data": [120, 200, 150] }]
   }
   ```
   ````

4. **容器尺寸**：每个图表默认高度 360 px、最小高度 240 px、宽度占阅读内容区 100%。支持 option 中安全的 `height` 数值或 CSS 长度作为后续扩展；首期不从文档执行自定义 CSS。
5. **主题与生命周期**：图表应匹配应用当前明暗主题；窗口或阅读栏尺寸变化后调用 `resize()`；切换文档、重新渲染、切换主题和组件销毁时正确 `dispose()`，不得遗留画布或监听器。
6. **失败降级**：JSON 解析、option 校验或图表初始化失败时，在原位置显示“ECharts 图表无法渲染”的错误卡片、简短原因和原始代码块折叠内容；不得使整篇文档渲染失败。
7. **安全与资源**：ECharts 及其依赖从本地应用包加载；禁止 `eval`、`new Function`、远程脚本和任意 URL 数据源。除用户点击的普通链接外，不应产生网络请求。

### 2.4 Mermaid 与其他扩展要求

1. Mermaid 仅渲染 fenced code block，使用其默认安全级别或等价的严格配置；不允许 HTML 标签、脚本、点击回调或任意 URL 注入。
2. Mermaid 解析失败时显示错误卡片和原始源码，不影响阅读位置、目录和其余 Markdown 内容。
3. 数学公式、脚注、Emoji、容器和文本装饰均在 HTML 净化前完成渲染；净化规则只保留扩展所需的标签、类名和 SVG 属性，禁止事件属性、内联脚本与危险 URL 协议。
4. CSS 在三种现有主题下均应可读；图表、图示和公式在窄窗口不溢出阅读栏，必要时允许其自身水平滚动。
5. 每篇文档可包含多个扩展块；单个块出错不影响其他块。首期不承诺离线导出为图片/PDF，也不承诺图表状态跨重新打开文档保留。

### 2.5 验收标准

- 打开含上述 P0 语法的 Markdown，普通内容、现有 GFM 内容和新增内容同时正确显示。
- 一个文档含三个 ECharts 图表时均独立显示；调整窗口宽度、切换三种主题后图表不重叠、不空白。
- 错误 JSON、无效 Mermaid 和非法公式只显示各自的降级提示，应用不崩溃，页面其他内容可继续阅读。
- `echarts` 代码块外的 JavaScript、HTML 以及任何函数文本均仅按普通内容处理，不会执行。
- 断网条件下打开已安装应用仍可预览 P0 语法，且渲染期间不产生外部网络请求。

## 3. 按文档记忆滚动位置

### 3.1 用户行为

1. 用户在阅读视图滚动任一文档后，切换到目录中另一篇文档，再返回原文档，应恢复至离开时的阅读位置。
2. 用户关闭并重新启动应用，再次从“最近打开”或目录打开同一文件，应恢复该位置。
3. 首次打开、用户手动点击目录标题、文档没有可滚动内容，或没有有效记录时，阅读栏从顶部开始。
4. 阅读进度条、当前大纲高亮与恢复后的实际可见内容保持一致。

### 3.2 存储模型与策略

本地持久化键建议为 `md-reader-scroll-positions-v1`，以规范化后的绝对文件路径为键；Windows 路径比较不区分大小写。单条记录包含：

```ts
interface ScrollPosition {
  filePath: string;
  modifiedAt: number;
  scrollTop: number;
  progress: number;       // 0–1，作为长度变化时的回退
  anchorId?: string;      // 最近已越过的 Markdown 标题 id
  anchorOffset?: number;  // 标题相对阅读栏顶部的偏移
  updatedAt: number;
}
```

- 在阅读栏滚动时以 250 ms 防抖更新内存记录；切换文件、切换视图、页面隐藏、窗口关闭和组件卸载前强制写入。
- 每次最多保留 500 篇、最近 180 天内的记录；超限或过期时按 `updatedAt` 清理。损坏的本地数据应被忽略并重新建立，不阻断打开文档。
- 打开文档后等待 Markdown、图片尺寸和预览扩展完成首轮布局，再恢复位置，避免渲染后跳动。
- 若记录的 `modifiedAt` 与当前文件一致，优先恢复 `scrollTop`，并限制在当前最大滚动范围内；不一致时优先以 `anchorId + anchorOffset` 恢复，找不到锚点则使用 `progress`，仍无效则从顶部开始。
- 用户在恢复开始后的首次主动滚动应立即接管，后续异步布局不得再次把视图跳回旧位置。

### 3.3 验收标准

- 对三个不同文件分别滚动至不同位置，任意顺序切换后每篇都恢复到对应位置，误差不超过一个正文行高。
- 重启应用后上述位置仍有效；删除/移动文件后不会引发异常。
- 修改文档并令原位置附近标题仍存在时，重新打开定位到该标题附近；标题被删除时按相对进度定位或从顶部开始。
- 很短文档、空文档、含大图表或含解析失败扩展的文档均不出现循环跳动、空白或越界滚动。

## 4. 源码编辑与保存

### 4.1 范围与入口

1. 在现有“源码视图”基础上，使用可编辑的纯文本编辑器替代只读 `<pre>`。首期支持所有当前可打开的 Markdown 与文本文件，并自动识别常见编码（UTF-8/16/32、GBK、Big5、Shift-JIS 等）；Markdown 的渲染预览仅适用于 Markdown 文件。
2. 用户可通过顶部“源码”按钮或快捷键进入编辑，阅读按钮返回预览。切回预览不自动写盘，只在内存中重新渲染当前文本。
3. 编辑器至少提供等宽字体、Tab 插入空格、行号、当前未保存状态标识和基础查找（`Ctrl+F`）。语法高亮、自动补全、多光标和实时双栏预览不属于首期必须项。
4. 保存入口为工具栏“保存”、`Ctrl+S`；没有打开文件、内容未改变或正在保存时按钮不可用。首期不提供“另存为”、新建文件或自动保存。

### 4.2 草稿、切换与预览同步

- 文档内存状态应区分 `diskContent`、`draftContent`、`isDirty`、`modifiedAt` 与保存状态。源码编辑的每次输入只更新 `draftContent` 和 `isDirty`。
- 发生文件切换、打开新文件/文件夹、从最近记录重新打开、尝试关闭窗口时，若当前文档有未保存修改，必须显示“保存 / 不保存 / 取消”。选择取消保持当前文档与光标不变；选择保存失败时不得继续丢弃草稿。
- 切换到阅读视图使用 `draftContent` 实时渲染；未保存标识仍保留。保存成功后将 `draftContent` 提升为 `diskContent` 并清除未保存状态。
- 保存后保留当前阅读滚动位置或编辑器光标/选择范围；无需回到文件顶部。

### 4.3 安全写入与冲突处理

1. 前端调用受限的 Tauri `save_reader_file(filePath, content, encoding, expectedModifiedAt)` 命令。后端必须重新校验目标是本进程已打开并授权的普通文件、扩展名受支持、大小不超过 25 MB，并按识别出的原编码编码写回，不能仅信任前端传入路径。
2. 写入前读取文件元数据并比对 `expectedModifiedAt`。若磁盘文件已被外部程序修改，拒绝直接覆盖并展示冲突对话框：
   - **重新加载**：放弃当前草稿并读取磁盘版本；
   - **覆盖保存**：用户二次确认后，以当前草稿覆盖；
   - **取消**：保留草稿，不写入磁盘。
3. 通过同目录临时文件加原子替换完成写入，并在失败后清理临时文件；写入过程不得留下截断的原文件。实现需尽量保留原文件的权限/只读属性，并报告权限不足、占用、磁盘空间不足等可理解错误。
4. 保留文件原有编码、BOM 和换行风格（CRLF/LF）；当前无法可靠识别的编码在打开时失败并给出原因，不能以错误编码保存造成损坏。
5. 保存成功后，后端返回更新后的 `content`、`modifiedAt` 等文件元数据；前端以返回值更新当前文档和滚动位置记录。

### 4.4 验收标准

- 编辑 Markdown、切回阅读视图后可看到尚未保存的正确预览；按 `Ctrl+S` 后重启应用，修改仍在磁盘文件中。
- 编辑后切换文件或关闭窗口会出现未保存确认；取消操作不会丢失内容。
- 两个程序同时修改同一文件时，MD Reader 保存不会静默覆盖外部修改，三个冲突选项均符合定义。
- 将目标设为只读、占用或写入失败时，显示错误、保留草稿和未保存标识，原文件内容不变。
- 保存包含中文、Emoji、公式、ECharts JSON、CRLF 的 Markdown 后，重新打开内容无乱码；预览与保存前一致。

## 5. 实施顺序与依赖

建议按以下顺序交付，减少编辑、预览和滚动恢复之间的耦合：

1. 将 Markdown 渲染管线扩展为固定内置的 P0 渲染器，并完善净化规则与错误降级；
2. 接入 ECharts、Mermaid 和 KaTeX 的本地依赖与响应式生命周期管理；
3. 建立按路径的滚动位置数据结构、恢复时机和清理策略；
4. 增加受限后端保存命令、原子写入和外部修改冲突检测；
5. 将源码视图接入编辑器，并接入未保存确认、快捷键和预览同步；
6. 按第 2.5、3.3、4.4 节完成手工验收，覆盖三种主题、离线环境和异常场景。

需要新增的主要依赖为 `echarts`、`mermaid`、数学公式渲染库以及对应的 Markdown-it 扩展；依赖须锁定版本并随应用打包，不能运行时从 CDN 加载。
